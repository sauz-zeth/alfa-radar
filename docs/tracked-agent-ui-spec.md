# Спецификация данных агента для вкладки «Отслеживаемое»

Дата проверки: 26 октября 2026 года.

Документ описывает текущий контракт интерфейса и рекомендуемый объём текста, который должен выдавать агент. Цель лимитов — чтобы данные помещались без переполнения на мобильном экране и не растягивали карточки на desktop.

## Точки входа

- Мобильный экран: `front/src/tracked/TrackedScreen.tsx` и `front/src/tracked/tracked.css`.
- Desktop-экран: `front/src/tracked/TrackedDesktop.tsx`, `TopicCard.tsx`, `tracked.css`, breakpoint `min-width: 1200px`.
- Подробная история после открытия: `front/src/event/EventScreen.tsx` и компоненты вкладок «Разбор», «Влияние», «Сценарии», «Действия», «Ход анализа», «Чат».
- API-контракт: `front/src/api/schemas/tracked.ts` и `front/src/api/schemas/insights.ts`.

Лимит символов ниже — рекомендация для генерации на русском языке вместе с пробелами, а не серверная валидация и не гарантия точного числа строк: перенос зависит от ширины колонки и шрифта. Сейчас API ограничивает длину пользовательского вопроса, но не большинство полей ответа агента. Для коротких полей в таблицах дана консервативная граница, чтобы снизить риск обрезания.

## A. Список «Отслеживаемое»

### Мобильная шапка

Размеры из CSS: верхняя область `.tracked-hero` — `100% × 476 px`; заголовок `27/35 px`; мета-строка `12/17 px`, без переноса.

| Поле | API-источник | Обязательность | Лимит |
| --- | --- | --- | ---: |
| Название экрана | фиксированное «Отслеживаемое» | всегда | не менять |
| Количество тем | `topics.length` | всегда | число |
| Количество обновлений | `changed || processing` | всегда | число |

### Мобильный активный круг темы

Размер круга `320 × 320 px`; внутренний контент `250 × 260 px`; заголовок максимум `228 px` по ширине, без заданного CSS line-clamp. Дата, тип влияния и индикатор обработки выводятся одной строкой (`white-space: nowrap`). Рекомендуемый лимит заголовка в 52 символа не гарантирует 2 строки, но уменьшает риск наложения.

| Поле | API-источник | Обязательность | Лимит |
| --- | --- | --- | ---: |
| Тип влияния | `event.impact_label` | да | 24 символа |
| Заголовок темы | `item.title` или `event.title` | да | 52 символа, 2 строки |
| Важность | `event.importance` | да | целое `0..100` |
| Число событий | `item.events.length` | да | число |

Кнопка открытия — только иконка `22.3 × 22.3 px`; текст в неё не передавать.

### Мобильные карточки «Без изменений»

Размер карточки `168 × 196 px`, внутренние отступы `16 px`. Заголовок `17/20 px`, CSS обрезает его до 3 строк. Важность отображается крупным числом `52 px`.

| Поле | API-источник | Лимит |
| --- | --- | ---: |
| Тип влияния | `event.impact_label` | 24 символа |
| Заголовок | `item.title` | 60 символов, максимум 3 строки |
| Важность | `event.importance` | `0..100` |

### Desktop-шапка и поиск

Контейнер максимум `1584 px`; шапка с отступами `20 px 28 px`; заголовок `34/39 px`; строка поиска `width: min(420px, 42%)`, высота `52 px`.

| Поле | API-источник | Лимит |
| --- | --- | ---: |
| Подпись количества | `storiesLabel(topics.length)` | 32 символа |
| Placeholder поиска | фиксированный | не менять |
| Ввод поиска | пользовательский | не ограничивать агентом |

### Desktop-карточка «Есть новое»

Карточка занимает ширину колонки, отступы `24 px`, скругление `28 px`. При наличии картинки: текстовая колонка + изображение `296 × 296 px`, радиус изображения `20 px`. Заголовок обрезается до 2 строк.

| Поле | API-источник | Лимит |
| --- | --- | ---: |
| Дата | `event.published_at` | короткая дата, 20 символов |
| Статус | `event.update_label` / служебный badge | 32 символа |
| Заголовок | `item.title` или `event.title` | 72 символа, 2 строки |
| Вопрос из «Что ждём» | `latestAnswer.text` без `?` | 90 символов, 2-3 строки |
| Вывод/ответ | последний отвеченный вопрос, затем `what_changed`, затем `summary` | 180 символов |
| Важность | `event.importance` | `0..100` |
| Тип влияния | `event.impact_label` | 24 символа |
| Число событий | `item.events.length` | число |
| Кнопка | фиксированное «Открыть» | не менять |

У обычной desktop-карточки вывод не имеет CSS line-clamp; compact-вариант обрезает его после 3 строк. Лимит 180 символов — ориентир агента, но не сохраняет одинаковую высоту обычных карточек при разной ширине окна.

### Desktop «Без изменений» и «Архив»

Compact-карточка повторяет desktop-карточку без картинки; вывод имеет CSS line-clamp `3` строки (`18/24 px`). Архивная строка располагается в правой колонке; заголовок имеет ellipsis в одну строку.

| Поле | Лимит |
| --- | ---: |
| Заголовок compact | 72 символа, 2 строки |
| Вывод compact | 160 символов, CSS обрезает после 3 строк |
| Заголовок архива | 64 символа, 1 строка |
| Дата + число событий | 40 символов |
| Кнопка | фиксированное «Возобновить», высота `44 px` |

## B. Шапка открытой истории

Открывается по `/event/:id`. На мобильном hero-контейнер имеет внутренние отступы `20 px`, радиус `36 px`; desktop — минимум `180 px` по высоте и отступы `24 px`.

| Поле | API-источник | Лимит |
| --- | --- | ---: |
| Источник · дата · число источников | `source_name`, `published_at`, `sources.length` | 80 символов |
| Заголовок истории | `title` | мобильный 80, desktop 120 символов; максимум 3 строки |
| Главная метрика | `impact_metrics[0]` | label 32, value 24 |
| Важность | `importance`, `impact_label` | `0..100`, label 24 |
| Что изменилось | `summary` / `fact.text` | 240 символов, 4 строки |
| Точки таймлайна | `timeline` | максимум 5 точек; `text` 54 символа на точку |

## C. Вкладка «Разбор»

Секции: «Что произошло», «Сравнение источников», «Для компании изменился расчёт», «Вопросы к истории», «Источники».

| Поле агента | API-ключ | Лимит |
| --- | --- | ---: |
| Факт | `summary` / `facts[]` | 240 символов |
| Тезис изменения | `theses[].text` | 180 символов каждый |
| Категория тезиса | `theses[].category` | 24 символа |
| Достоверность | `theses[].status` | 32 символа |
| Сходятся | `comparison.agree[]` | до 2 строк по 160 символов |
| Расходятся | `comparison.differ[]` | до 3 строк по 160 символов |
| Один источник | `comparison.single[]` | до 3 строк по 140 символов |
| Метрика компании | `impact_metrics[]` | максимум 3 метрики; label 42, value 24, note 100 |
| Почему это важно | `what_it_means` / `why_important` | 220 символов |
| Вопрос | `open_questions[].text` | 110 символов |
| Ответ на вопрос | `open_questions[].answer` | 220 символов |
| Источник ответа | `source` | 48 символов |
| Карточка источника | `sources[]` | `text` до 240 символов |

Не создавать больше 5 тезисов, 3 групп сравнения и 4 карточек источников. Это объём выдачи, не ограничение CSS/API: исходная страница отображает все переданные элементы.

## D. Вкладка «Влияние»

Карточки и сетки рассчитаны на короткие значения. Порядок `impact_metrics` важен: первые три используются как основные метрики.

| Поле | API-ключ | Лимит |
| --- | --- | ---: |
| Значение пересчёта | `impact_metrics[].value` | 24 символа |
| Название пересчёта | `impact_metrics[].label` | 42 символа |
| Было / пояснение | `previous_value`, `note` | 100 символов |
| Компонент оценки | `score_breakdown[]` | максимум 5; label 32, text 120 |
| Цепочка «Событие» | `title` | 100 символов |
| Цепочка «Фактор» | `impact_metrics[].label` или тезис | 120 символов |
| Цепочка «Последствие» | главный metric / `what_it_means` | 140 символов |
| Факт профиля | `profileFacts` | value 24, label 48 |
| Риск или возможность | `theses[]` | максимум 4, text 180, meta 60 |
| Аналитика банка | `alfa.author`, `alfa.text` | author 48, text 280 |

Если данных профиля не хватает, передавать короткое объяснение причины и один требуемый параметр в `needs_profile`; не заполнять карточку выдуманным числом.

## E. Вкладка «Сценарии»

Поддерживаемые горизонты только `3m`, `6m`, `12m`. На desktop три сценарные карточки стоят в сетке; каждая имеет минимум `280 px` высоты и внутренние отступы `28 px`.

| Поле | API-ключ | Лимит |
| --- | --- | ---: |
| Рычаг / главное допущение | `lever_label`, `assumptions[].label` | 120 символов |
| Значения рычага | `lever_values[]` | максимум 3 значения по 16 символов |
| Название сценария | `scenarios[].name` | 24 символа |
| Доля / допущение | `scenarios[].share` | 16 символов |
| Эффект | `effect_label` | 24 символа |
| Вероятность | `probability` | `0..100%` |
| Пояснение сценария | `scenarios[].note` | 140 символов |
| Формула | `scenarios[].formula` | 80 символов |
| Происхождение | `scenarios[].origin` | 32 символа |
| Пояснение прогноза | `forecast_note` | 180 символов |
| Открытый вопрос | `open_questions[].text` | 110 символов |
| Ответ | `open_questions[].answer` | 220 символов |

Если сценарии рассчитаны, отдавать три в порядке: «Пессимистичный», «Базовый», «Оптимистичный». Текущая функция построения сценариев сама рассчитывает эти три сценария по профилю и важности; при отсутствии выручки возвращает `needs_profile`, пустые `scenarios` и `assumptions`.

## F. Вкладка «Действия»

На desktop основной план ограничен шириной `1120 px`. Основное действие и дополнительные действия нумеруются интерфейсом.

| Поле | API-ключ | Лимит |
| --- | --- | ---: |
| Название действия | `actions[].title` | 100 символов |
| Описание | `actions[].description` | 180 символов |
| Роль | `actions[].role` | 48 символов |
| Срок | `deadline` / `deadline_label` | 24 символа |
| Происхождение | `origin` | 24 символа |
| Чек-лист | `checklist[]` | максимум 6 пунктов по 100 символов |
| Продукт банка | `product.name` | 48 символов |
| Описание продукта | `product.description` | 160 символов |
| Польза | `product.benefit` | 160 символов |

Текущий fallback обычно формирует несколько действий, а LLM может вернуть свой список. Рекомендуемый объём для равномерной высоты — 1 основное и до 2 дополнительных, но это не ограничено схемой или компонентом. Не создавать действия без конкретного глагола, ответственного и срока.

## G. Вкладка «Ход анализа»

Журнал строится из `agent_log`. На desktop рядом с журналом есть блок статистики; на мобильном журнал идёт одной колонкой.

| Поле | API-ключ | Лимит |
| --- | --- | ---: |
| Тип шага | `agent_steps[].type` | 24 символа |
| Время | `agent_steps[].at` | 16 символов |
| Текст шага | `agent_steps[].text` | 180 символов |
| Исправление | `is_correction` | boolean |

Рекомендуемый журнал: 4–8 шагов. Компонент показывает все пришедшие шаги, высота не фиксирована. Каждый шаг должен описывать одно действие агента: источник данных, проверка, расчёт, самопроверка или исправление. Не писать в журнал полный внутренний промпт или длинное рассуждение.

## H. Вкладка «Чат»

Поле ввода пользователя не ограничивается агентом, но ответ агента должен оставаться компактным.

| Поле | API-ключ | Лимит |
| --- | --- | ---: |
| Рекомендуемый вопрос | `open_questions[].text` | 110 символов |
| Быстрый вопрос | фиксированный или `chat[].question` | 80 символов |
| Ответ | `chat[].answer` | 600 символов; 5–8 коротких строк |
| Происхождение | `chat[].origin` | 32 символа |
| Ссылка на первоисточник | `source.url` | URL без отображения длинного текста |

В сохранённом чате нет CSS-лимита длины ответа, поэтому 600 символов — рекомендация для компактности, не гарантия фиксированной высоты. Ответ должен начинаться с вывода, затем давать 1–3 подтверждающих факта. Если данных нет, писать это прямо и не подставлять предположение.

## I. Общие правила агентского цикла

1. Сначала заполнить структурированные значения и числа, затем короткие подписи и пояснения.
2. Не повторять один и тот же факт в `summary`, `what_changed`, `conclusion` и `answer`; для карточки выбирать один лучший текст.
3. Числа, валюты, проценты и даты не округлять до потери смысла; форматировать компактно (`1,2 млрд ₽`, `15%`, `3 дня`).
4. Пустое значение лучше, чем выдуманный текст. Для нехватки профиля использовать `needs_profile`.
5. Не передавать переносы строк в коротких label/value; длинные тексты разбивать на предложения.
6. Максимум 5 точек таймлайна, 3 метрики, 3 сценария, 6 пунктов чек-листа и 8 шагов журнала.
7. После генерации выполнить проверку длины по таблицам выше и сократить превышения до записи `report`.

## Ограничение проверки

Проверка выполнена по исходному DOM/CSS и API-схемам. В текущем окружении отсутствуют `bun` и установленный браузерный раннер, поэтому реальные Playwright-скриншоты на viewport не снимались. Перед выпуском агентского цикла нужно прогнать desktop `1440×900` и мобильные `390×844` и `412×915`, проверив отсутствие горизонтального скролла и наложения текста. Некоторые desktop-поля уже обрезаются (`topic-card__desk-title`, compact-вывод и заголовок архива); в остальных случаях лимит длины лишь уменьшает риск, но не заменяет визуальный тест.
