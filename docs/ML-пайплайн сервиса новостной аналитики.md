# ML-пайплайн сервиса новостной аналитики

Oct 15, 2026 · @alex

## Кратко

Пайплайн превращает поток новостей в короткую ленту событий, важных для конкретной компании. Дешёвые модели фильтруют поток, LLM оценивает только отобранных кандидатов.

Шаги 1–2 считаются один раз на новость, шаги 3–5 — на пару «событие + компания» и кешируются, шаг 6 — на пользователя.

&#91;embedded content: ML-пайплайн · 6 онлайн-шагов, 3 офлайн-блока\]

Слева онлайн-поток, справа офлайн-подготовка, которая его питает: до дорогого шага 5 доходят только события, прошедшие предскоринг.

## Офлайн-подготовка

До запуска готовятся три вещи: классификатор категорий, профили компаний и порог отбора τ.

### Классификатор категорий

1. LLM размечает около 5000 новостей по \~30 категориям-факторам: ставка, курс, сырьё, санкции, регулирование, спрос и т.д. У новости может быть несколько категорий.
2. 200 примеров проверяются вручную, они же служат тестовой выборкой.
3. ruBERT дообучается с multi-label головой: сигмоида + BCE.
4. Для каждой категории на валидации подбирается порог t\_c по максимуму F1.

### Профиль компании

LLM строит профиль по отчётности и открытым источникам, пользователь может его править. Вес категории w\_c ставится по якорной шкале, для весов от 0.6 модель пишет короткое обоснование.

| w\_c | Смысл |
| --- | --- |
| 1.0 | фактор прямо входит в выручку или себестоимость |
| 0.6 | заметное косвенное влияние на спрос или затраты |
| 0.3 | фоновое влияние |
| 0 | связи нет |

Пример профиля, сокращённо:

```json
{
  "description": "Продуктовый ритейлер, магазины на юге России",
  "factors": [
    {"category": "спрос", "w": 1.0, "why": "выручка = трафик × средний чек"},
    {"category": "ставка", "w": 0.6, "why": "кредиты на открытие магазинов"}
  ],
  "entities": [
    {"name": "Магнит", "role": "competitor",
     "aliases": ["пао магнит", "сеть магнит", "mgnt"]},
    {"name": "Краснодарский край", "role": "region",
     "aliases": ["краснодарский край", "кубань"]}
  ]
}
```

- Роли сущностей: self, client, supplier, competitor, region. Роль передаётся в LLM как контекст.
- Алиасы хранятся в начальной форме и нижнем регистре.
- Названия, совпадающие с обычными словами («Магнит», «Лента»), записываются только в контекстных вариантах: «пао магнит», «сеть магнит», тикер.

### Порог отбора τ

1. Золотой набор: около 300 событий × 3–5 тестовых компаний. LLM оценивает все пары, 100 пар проверяются вручную.
2. Важным считается событие с I ≥ 50 (формула I — в шаге 5).
3. τ выбирается по кривой «recall важных событий против доли событий, ушедших в LLM»: минимальная доля при recall 0.9–0.95.

## Шаг 1. Обогащение новости

Каждая новость обрабатывается один раз для всех пользователей.

| Модель | Что даёт |
| --- | --- |
| ruBERT, дообученный | вероятности категорий p\_c |
| pymorphy3 | леммы текста для поиска алиасов из профиля |
| Эмбеддер предложений, без дообучения | вектор новости для кластеризации |

## Шаг 2. Кластеризация в события

Новости об одном факте объединяются в событие: так считаются независимые источники и не показываются дубли.

1. Эмбеддинг новости сравнивается с центроидами событий, в которые приходили новости за последние 2 часа.
2. Косинусная близость ≥ θ — новость добавляется к событию как ещё один источник, иначе создаётся новое событие. θ ≈ 0.85, точнее подбирается на 100 размеченных парах.
3. Один источник даёт событию не больше одной новости: повторная публикация того же источника заменяет прежнюю.

Дальше используются агрегаты события:

- p\_c — максимум по новостям события;
- леммы — объединение по всем новостям;
- n\_src — число источников;
- t0 — время первой новости.

## Шаг 3. Предскоринг по категориям

Для каждой компании событие получает скор S\_cat от 0 до 1: насколько его темы задевают факторы компании.

```latex
\tilde p_c = \max\left(0,\ \frac{p_c - t_c}{1 - t_c}\right)
```

```latex
S_{cat} = 1 - \prod_c \left(1 - w_c \cdot \tilde p_c\right)
```

- Срез по порогу t\_c убирает шум. Размытая новость с p = 0.15 по десяти категориям даёт 0, простая сумма при весах 0.6 дала бы 0.9.
- Noisy-OR: одного сильного канала влияния достаточно, несколько каналов усиливают скор, но он не превышает 1.
- Шкала одна для всех компаний, поэтому работает общий порог τ.

## Шаг 4. Упоминания и отбор в LLM

В LLM идут события с S\_cat ≥ τ, а также события с упоминанием компании или её контрагентов, даже при низком S\_cat.

### Поиск упоминаний

Алиасы из профиля ищутся по леммам текста события: своя компания, ключевые клиенты и поставщики, конкуренты, регионы. Так ловятся новости о конкретных игроках, которые BERT не связывает с категориями: пожар у поставщика, сделка конкурента.

### Правила отбора

1. S\_cat ≥ τ или найден алиас из профиля — событие идёт в LLM.
2. Не больше K вызовов в час на компанию, например K = 20. При превышении первыми идут события с упоминаниями, затем по убыванию S\_cat.

Когда к событию приходит новый источник, S\_cat пересчитывается. LLM вызывается повторно, только если S\_cat вырос на 0.15 и больше или появилось новое упоминание; иначе оценка берётся из кеша «событие + компания».

## Шаг 5. LLM-анализ

LLM получает событие и профиль компании и возвращает оценки по шкале 1–5; итоговую важность I считает формула, а не модель.

Вход: заголовки и тексты до 3 источников события, профиль компании, сработавшие категории и найденные упоминания. Ответ проверяется Pydantic-схемой, при ошибке запрос повторяется.

| Поле | Тип | Смысл |
| --- | --- | --- |
| materiality | 1–5 | влияние на выручку или затраты компании |
| certainty | 1–5 | 5 — событие состоялось и подтверждено, 1 — слух или прогноз |
| horizon | hours / days / weeks | как долго событие актуально |
| impact | risk / opportunity | тип влияния |
| why | строка | одна фраза «почему важно» для карточки |

```latex
I = 20 \cdot M \cdot \left(0.6 + 0.4 \cdot \frac{C}{5}\right)
```

M — materiality, C — certainty, I от 14 до 100. Оценки 1–5 по понятным критериям стабильнее, чем число 0–100 от модели. События с I < 30 уходят в раздел «Без влияния».

## Шаг 6. Ранжирование ленты

Лента пользователя сортируется по R: важность события затухает со временем и поправляется на число источников и личные предпочтения.

```latex
R = \frac{I}{100} \cdot 0.5^{\,age/h} \cdot T \cdot U
```

| Величина | Как считается |
| --- | --- |
| age | часы с первой новости события |
| h, период полураспада | из horizon: hours — 8 ч, days — 24 ч, weeks — 72 ч |
| T, подтверждённость | 0.85 при 1 источнике, 0.95 при 2, 1.0 при 3 и больше |
| U, личный множитель | из свайпов, см. следующий раздел |

### Правила подборки

1. Непросмотренные события с I ≥ 85 — в блок «Срочно» сверху, не больше двух.
2. Остальные новые события с последнего визита — по убыванию R, в подборку попадают первые 7.
3. Разнообразие: каждая следующая карточка с той же главной категорией умножается на 0.7^k, где k — сколько таких карточек уже выше.

## Обратная связь от свайпов

Свайпы меняют только личный множитель пользователя U, веса профиля общие для компании и не меняются. Так два руководителя одной компании получают разные ленты, а кеш шагов 3–5 остаётся общим.

Сигнал свайпа распределяется по категориям события пропорционально p̃\_c.

| Действие | Счётчики категории c |
| --- | --- |
| свайп вправо | L\_c += p̃\_c |
| влево, «неинтересно» | D\_c += p̃\_c |
| влево, «ошибка подборки» | D\_c += 2 · p̃\_c, событие пишется в лог для правки профиля |
| влево без причины | D\_c += 0.5 · p̃\_c |
| влево, «неактуально» или «уже видел» | не меняются: это ошибка времени жизни или кластеризации |

```latex
U_c = \mathrm{clip}\left(e^{\,0.7 \cdot \frac{L_c - D_c}{L_c + D_c + 5}},\ 0.5,\ 1.5\right)
```

```latex
U = \frac{\sum_c \tilde p_c \, U_c}{\sum_c \tilde p_c}
```

Слагаемое 5 в знаменателе сглаживает реакцию: один свайп не перекраивает ленту. Если событие прошло только по упоминанию и категорий у него нет, U = 1.

## Метрики качества

Каждый компонент проверяется на своём размеченном наборе, продукт в целом — по доле событий, приведших к действию.

| Компонент | Метрика | Данные |
| --- | --- | --- |
| Классификатор | macro-F1 | 200 проверенных вручную новостей |
| Кластеризация | precision и recall пар «одно событие» | 100 размеченных пар |
| Предскоринг | recall важных событий, доля событий в LLM | золотой набор |
| LLM-анализ | совпадение I и impact с ручной оценкой | 100 проверенных пар золотого набора |
| Лента | доля свайпов вправо в топ-5; North Star — доля событий, приведших к действию | логи пользователей |
