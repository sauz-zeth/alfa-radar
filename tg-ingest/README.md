# tg-ingest — Telegram-селфбот для бэкенда

Отдельный сервис: логинится в Telegram как обычный человек, подписывается на каналы,
которые пользователи добавили в систему, слушает новые посты и отправляет их в
`POST /api/ingest/posts` бэкенда с заголовком `X-Ingest-Token`.

## Запуск

```bash
cd tg-ingest
cp .env.example .env        # заполнить TG_API_ID, TG_API_HASH, TG_PHONE, INGEST_TOKEN
uv sync
uv run tg-ingest login      # один раз: ввести код из Telegram (и пароль 2FA, если включён)
uv run tg-ingest run        # слушать новые посты
```

`TG_API_ID` и `TG_API_HASH` берутся на https://my.telegram.org → API development tools.

Это userbot: Telegram может ограничить аккаунт за автоматизацию. Для сервиса лучше
использовать отдельный реальный аккаунт, а не основной.

### Первый вход без интерактива (прод/Docker)

`TG_PHONE` можно держать в секретах, а код подтверждения — нет, его вводит человек.
Если сессии ещё нет, `run` поднимает маленькую веб-страницу настройки:

1. В `.env` задать `TG_API_ID`, `TG_API_HASH`, `TG_PHONE`, `INGEST_TOKEN`.
2. Запустить сервис.
3. Открыть `http://<host>:8081/setup` (в Docker порт публикуется из `docker-compose.yml`).
4. Ввести `INGEST_TOKEN`, нажать «Отправить код», ввести код из Telegram.
5. Если включена 2FA — ввести пароль на той же странице.

После успеха страница показывает «Готово», а сервис сразу начинает слушать каналы.
Сессия сохраняется в `TG_STATE_DIR`, поэтому при следующем запуске страница настройки
уже не поднимается. Если нужен ручной вход, используйте `uv run tg-ingest login`
или выставьте `SETUP_ENABLED=false`.

Порт настройки по умолчанию слушает `127.0.0.1:8081`; в Docker — `0.0.0.0:8081`
(пробрасывается наружу). Все действия требуют `X-Ingest-Token`, сам токен страница
не хранит на сервере.

### Docker

```bash
cd tg-ingest
cp .env.example .env   # заполнить TG_* и INGEST_TOKEN
docker compose up -d --build
# открыть http://<host>:8081/setup
```

По умолчанию состояние лежит в `./state` и монтируется в `/state` контейнера;
compose принудительно кладёт туда сессию и счётчик подписок. Кастомная папка на хосте:

```bash
TG_STATE_DIR_HOST=/srv/alfa/tg-state docker compose up -d
```

Если бэкенд запущен в соседнем compose-проекте, укажите его адрес:

```bash
TG_BACKEND_URL=http://api:8000 docker compose up -d
```

### Про креды

Пароль нигде не сохраняется. Telethon после первого входа пишет SQLite-файл сессии
в `TG_STATE_DIR` (`state/tg_ingest.session` по умолчанию) и дальше авторизуется им.
Это фактический ключ доступа к аккаунту: не коммитьте его, храните с правами `600`,
а для Docker/systemd смонтируйте `TG_STATE_DIR` как volume.

## Что делает

- Раз в `CHANNELS_SYNC_INTERVAL` секунд забирает из бэкенда
  `GET /api/ingest/channels` — каталог каналов и число подписчиков из
  `profile_channels` — и подписывает твинка на каналы, у которых есть подписчики.
- Тянет аватарки каналов через Telethon и загружает их в кэш бэкенда
  (`PUT /api/ingest/channels/{id}/avatar`), а также обновляет закэшированное число
  подписчиков (`PUT /api/ingest/channels/{id}/stats`), чтобы фронт показывал реальные
  картинки и цифры.
- Ловит новые посты только из каналов с подписчиками. `TG_CHANNELS` добавляет каналы
  вручную (например, если бэкенд недоступен или канал ещё никому не нужен).
- Игнорирует группы, личные переписки и посты без текста/подписи.
- Формирует `source_name`, `url` (`t.me/...` или `t.me/c/...`) и `published_at`,
  отправляет пост в бэкенд с ретраями (3 попытки с backoff).
- Если подписку удалили из бэкенда, твинк перестаёт форвардить канал; из самого
  Telegram аккаунт при этом не выходит.
- Вступления искусственно замедлены: случайная пауза `JOIN_DELAY_MIN..JOIN_DELAY_MAX`
  секунд и не больше `JOIN_BATCH` каналов за цикл. Дневной лимит выключен
  (`JOIN_DAILY_LIMIT=0`); можно задать число, если он нужен.
  Аватарки докачиваются отдельными порциями (`AVATAR_BATCH`) и не задерживают подписки.
  Счётчик лежит в `JOIN_STATE` (`state/joins.json`) и переживает рестарт. Это снижает
  риск бана, но не даёт гарантии: лимиты Telegram не публикует.
- Пропущенные за время простоя апдейты Telethon добирает при следующем подключении
  (catch-up), полного backfill истории нет.

Каналы с ошибкой (неверный `@handle`, приватный канал) логируются и повторяются
не чаще раза в `CHANNEL_JOIN_RETRY` секунд. Аккаунт в Telegram должен иметь доступ
к каналу: публичный канал твинк джойнит сам, приватный — только если уже состоит.

## Формат запроса в бэкенд

```http
POST /api/ingest/posts
X-Ingest-Token: <INGEST_TOKEN>

{
  "text": "...",
  "source_name": "Металл-Инсайд",
  "channel": "@metall_inside",
  "url": "https://t.me/metall_inside/42",
  "published_at": "2026-10-25T12:00:00+00:00",
  "telegram": {"chat_id": 1234567890, "message_id": 42, "username": "metall_inside"}
}
```

`profile_id` не передаётся: пост попадает в таблицу `posts` и проходит глобальные
стадии пайплайна (parse → classify → cluster). В ленту он не попадает, потому что
лента строится на уровне профиля. Если нужна привязка к конкретному профилю,
добавьте `profile_id` в payload.
