# Кандидатогенерация и ранжирование новостей

Запускать из каталога `ml_artifact/`. Для готового корпуса нужны только Python 3.10+
и стандартная библиотека; зависимости ruBERT/E5 здесь не загружаются.
Ключ читается из ALFA_LLM_API_KEY в окружении или `ml_artifact/.env` и не попадает в отчёты.

## Запуск

Профили всех 15 бизнесов и кандидаты **без API**:

    python3 final/select_business_news.py

Результат: outputs/business_news.json и outputs/business_news.html.
В HTML у каждой категории есть выбор «прямое / косвенное / не важно».
Кнопка «Скачать профили JSON» сохраняет настройки. Чтобы применить их к
расчёту, передайте скачанный файл через --profiles. Редактирование HTML
само по себе не пересчитывает готовые карточки.

Предпросмотр одной компании без API:

    python3 final/rank_business_news.py --uid U_71020 --dry-run

Первичная оценка Gemma и отдельный полный анализ Qwen для одной компании:

    python3 final/rank_business_news.py --uid U_71020

Результат: outputs/business_ranking/ranked.html и ranked.json.
Метрики сохраняются автоматически в `ranked_metrics.json`, в разделе метрик HTML,
а также в `runs/<run_id>.metrics.json` для каждого завершённого запуска.
`current_run` содержит реальные вызовы и расходы текущего запуска; `result_analysis` —
известные исходные вызовы для результатов, включая загруженные из кеша. Эти суммы
не складываются. Повторные и неуспешные вызовы учитываются; отсутствующий usage
отмечается как неизвестный. Воронка отдельно показывает весь корпус, отбор
источников компании и фактически обработанные события (с учётом `--limit`).
CPU-время ruBERT доступно только при наличии замеров в файле кластеров;
из кеша предсказаний восстановить эти замеры нельзя. Метрики качества требуют разметки.
Предпросмотр записывается отдельно: preview.html и preview.json.
На macOS открыть отчёт можно командой:

    open outputs/business_ranking/ranked.html

Короткая проверка API и применение своего профиля:

    python3 final/rank_business_news.py --uid U_71020 --limit 10 --profiles business_profiles.json

--limit ограничивает число входных кластеров (по времени), а не число
рекомендаций или вызовов. Без --limit обрабатывается весь корпус.
HTML автономный: поиск, фильтр категории и дат UTC, сортировка, пагинация,
исходные тексты и JSON. Разделы: лента, слабое влияние, отслеживаемое,
кандидаты без оценки, не важно, реклама/мусор, ошибки.

## Соответствие pipeline.md

Скрипт rank_business_news.py выполняет **шаги 3–7 на готовых кластерах**.
Шаги 1–2 — существующие ruBERT/E5 и кластеризация. Скрипт не загружает модели
повторно и не перекластеризует данные. Вход по умолчанию:
outputs/cluster_explorer/clusters_78735240aa4b.json, публикации за
22–23 октября 2025 года. У этого корпуса порог 0.955 и порог слияния 0.94,
что отличается от 0.91 в pipeline.md. Об этом есть предупреждение в терминале;
параметры корпуса видны в HTML. Для расчёта на кластерах с порогом 0.91
передайте соответствующий JSON через --clusters.

1. Реклама/мусор исключается до LLM по порогу классификатора.
2. Если независимых источников >5, сразу вызывается Qwen, включая определение
   продолжения тем при непустом --topics. Иначе Gemma проверяет продолжение тем.
   Обновления отправляются только в «Отслеживаемое», даже если категории
   не имеют влияния. При пустом списке тем этот вызов не нужен.
3. ruBERT-категория активна при p >= порога из metadata.json.
   Уровень события — максимальный уровень среди активных категорий.
   Старых числовых весов, нормировки вероятности и порога 0.94 больше нет.
4. При ≤5 независимых источниках «Не важно» не вызывает оценку. «Косвенное» → Gemma.
   При I₁ >= 50 → независимый Qwen. «Прямое» → сразу Qwen.
   Оценка Gemma не передаётся в запрос полного анализа.
5. I = 20 × M × D × U. Окончательная оценка Qwen заменяет оценку Gemma.
   I >= 30 → лента; иначе → слабое влияние.
6. Уже обработанный event_id с тем же исходным первым постом получает
   обновлённые публикации и число источников без повторного анализа, кроме
   первого пересечения порога >5, если Qwen ещё не анализировал событие.
   Идентификаторы событий должны быть стабильными между обновлениями корпуса.

Первичная модель: google/gemma-4-26b-a4b-it. Полный анализ:
qwen/qwen3.6-35b-a3b. Полный анализ выполняется
отдельным запросом с полным профилем, без передачи первичной оценки.
Основной и резервный API-адреса настроены по инструкции команды. Сетевые
ошибки, HTTP 429/5xx и некорректные ответы повторяются с резервным адресом.
Параметры: --base-url, --fallback-url, --timeout (120 с), --attempts (3).
Пустой --fallback-url отключает резервный адрес. При ошибке авторизации или
исчерпании повторов запуск останавливается, сохраняет частичный результат
и возвращает ненулевой код. Повтор команды продолжает расчёт.

## Принятые настройки шкал

В pipeline.md не определены коэффициенты D/U и формула свежести.
В этой реализации явно приняты следующие значения, не результат калибровки:

| Шкала | Значения |
|---|---|
| M | целое 1–5 |
| D | прямое: 1; косвенное: 0.5; фоновое: 0.25 |
| U | срочно: 1; в ближайший месяц: 0.75; не срочно: 0.5 |
| Ранжирование | I × 2^(-возраст в часах / 72) |

Категориальное влияние профиля определяет маршрут, а шкала прямоты LLM —
оценку конкретной новости. Это разные величины. Важность находится в 0–100;
фильтр ленты применяется к I до поправки на свежесть.
--half-life-hours меняет период полураспада. По умолчанию дата расчёта —
последняя дата корпуса, чтобы архив 2025 года был пригоден для демонстрации.
Для актуальной ленты передайте --as-of с нужной датой ISO и часовым поясом.
Дата и коэффициенты сохраняются в отчёте.

Начальные уровни профилей — эвристики по ОКВЭД, ВЭД, кредиту/лизингу и
стадии роста. Отраслевая категория, валютные/санкционные/таможенные факторы
для ВЭД, ставка для заёмщиков и господдержка для растущего бизнеса — прямые.
Общие экономические факторы — косвенные; остальные категории — «не важно».
Настройки следует уточнять под конкретную компанию через HTML/--profiles.

## Темы и дополнительный контекст

--topics принимает JSON-массив тем **выбранной компании**:

    [{"topic_id":"tax-2025","title":"Изменение налогов","summary":"Обсуждение новых ставок"}]

--context принимает объект с выжимкой отчётности и фрагментами аналитики:

    {"financial_summary":"Выручка ...", "bank_analytics":[{"title":"Обзор","text":"Текст обзора","source":"Источник"}]}

При отсутствии контекста отчётность не выдумывается, позиция банка — null.
Для Gemma используются сжатый профиль и найденные упоминания имени, ИНН,
региона (если эти поля есть). Qwen получает полный аккаунт и профиль.
Тексты всех источников представлены в запросе с общим бюджетом 18 000 символов
и флагом truncated у сокращённых текстов. Полные публикации остаются в отчёте.

## Прогресс и повторный запуск

Терминал показывает индекс/число кластеров, процент, этап, модель, попытку,
время ожидания каждые 15 секунд, I₁, результат и примерное оставшееся время.
JSON и HTML обновляются после каждого кластера. HTML нужно обновить в браузере.
Ctrl+C сохраняет частичный отчёт. В output-dir сохраняются state/ и api_cache/;
повтор команды использует их. Изменение профиля, тем или контекста создаёт
отдельное состояние и пересчитывает зависимые оценки. Для нескольких компаний
удобно задавать отдельный --output-dir. Не запускайте два процесса с одним
output-dir одновременно. Кэш и отчёты содержат тексты новостей и профиль.

Проверки:

    python3 -m unittest discover -s tests -p 'test_*business_news*.py'

## Метрики теста, токены и стоимость

В ranked.html добавлена сводка теста и таблица каждой новости. Эти же данные
сохраняются в ranked_metrics.json (для dry-run — preview_metrics.json),
в поле metrics основного JSON и в архиве runs/<run_id>.metrics.json.
В HTML есть кнопка скачивания метрик JSON. requests.jsonl — журнал всех
API-попыток и обращений к кэшу с run_id, event_id, моделью и этапом,
без ключа API и содержимого запросов. Архив не затирается следующим запуском.

Измеряются:

- время подготовки, обработки события, запросов и экспорта предыдущих
  снимков; суммарное время, скорость событий/мин, среднее, p50, p95;
- входные, выходные, reasoning- и кэшированные входные токены;
- фактическая стоимость usage.cost по каждому ответу, модели, этапу и новости;
- средние расходы/токены по всем событиям и отдельно по событиям с API;
- переходы Gemma → Qwen и их доля от первичных оценок Gemma, прямые
  маршруты Qwen, завершённые перепроверки, изменение I после перепроверки,
  сколько оценок упало ниже 50 и сколько новостей ушло из ленты;
- вызовы, повторы, резервный адрес, ошибки сети, HTTP 429/5xx, невалидные
  ответы, попадания в кэш и восстановления состояния;
- распределение влияния, маршрутов, итоговых разделов, важности, числа
  источников, количество публикаций и доля событий, попавших в ленту.

Единица новости — **кластер**, не публикация. Время измеряется для шагов
3–7 и не включает ранее выполненные ruBERT/E5. p95 — линейно интерполированный
процентиль наблюдений, а не гарантия задержки; для малого теста выборка мала.
Метрики всего запуска не меняются при фильтрации ленты.

API шлюза возвращает usage.cost, но в проверенных ответах не сообщает валюту,
а каталог /models не содержит тарифов. По умолчанию стоимость подписана API
(единицы стоимости шлюза). Когда валюта подтверждена организаторами, укажите
--cost-currency RUB или --cost-currency USD. Флаг только подписывает единицы,
он **не конвертирует** деньги и не меняет уже сохранённые метаданные кэша.

Если API не вернул cost, можно передать --pricing с подтверждёнными тарифами:
JSON-объект с полями currency и models. Ключи models — точные имена моделей;
для каждой задаются input_per_million и output_per_million, при необходимости
cached_input_per_million. Все тарифы — неотрицательные числа за миллион токенов.
Расчётная стоимость помечается estimate и отделяется от api. Разные валюты
не складываются. При отсутствии тарифа и cost показывается «нет данных».

Токены и расходы учитываются и при невалидном ответе, если API вернул usage.
Таймаут/HTTP-ошибка без usage означает неизвестный расход, а не бесплатный
запрос. Таблицы показывают полноту измерений и известную часть суммы.
Reasoning входит в output; кэшированные токены входят в input — повторно
к total они не прибавляются.

current_run показывает новые расходы этого запуска. result_analysis и
колонки «анализ» сохраняют измерения исходных запросов результатов из кэша;
повторный просмотр не списывает стоимость второй раз. Старые кэши, созданные
до внедрения метрик, не содержат usage и времени — это явно отмечено.
Исторические метрики относятся к сохранённому анализу результатов, а не ко
всем когда-либо выполненным неудачным запускам: для полного аудита есть
requests.jsonl и архив runs/. Ctrl+C сохраняет также телеметрию прерванного
события. SIGKILL/отключение питания может оставить последнюю попытку без
финальной записи; невозможно приписывать ей нулевую стоимость.

Для чистого теста используйте новый output-dir, например:

    python3 final/rank_business_news.py --uid U_71020 --limit 20 --output-dir outputs/business_metrics_test_new

Precision, recall, NDCG и точность ответов без эталонной разметки не считаются.

Дополнительные проверки метрик:

    python3 -m unittest discover -s tests -p 'test_news_metrics.py'


## Ограничения профиля и подборки каналов

Активными считаются категории «прямое» и «косвенное»: **не более 8 в сумме**.
При построении стартового профиля сначала сохраняются прямые воздействия,
затем отраслевые косвенные и общие факторы. Остальные — «не важно».
HTML блокирует девятую активную категорию. --profiles с превышением лимита
завершает запуск с ошибкой, без автоматического изменения пользовательского выбора.

Индивидуальная подборка строится из каталога RSS по отрасли и профилю компании,
с деловыми СМИ, официальными решениями, правом и налогами в общей части. Подборка
не зависит от оценок LLM или объёма публикаций.

Оба скрипта принимают --sources с конфигурацией того же формата. Для нового
UID применяется отраслевая политика business_source_selection.py. Публикации
чужих каналов исключаются **до** определения категорий, вызовов LLM и подсчёта
независимых источников. Метки берутся из оставшихся публикаций; метки всего
кластера используются как запасной вариант только если ничего не исключалось.
Канал без публикаций в текущем корпусе остаётся в подборке, но не увеличивает
счётчик источников события. Отчёт содержит source_filter с числом исключённых
публикаций и списком выбранных каналов без публикаций.

Правило **>5 независимых групп → сразу Qwen** описано в pipeline.md, шаг 2а.
Оно действует даже без совпавших категорий, но не отменяет исключение рекламы
и фильтр разрешённых каналов. Отслеживаемые темы в этом случае проверяет Qwen;
обновления по-прежнему не попадают в основную ленту. Известные связанные каналы
и указанный в метаданных общий первоисточник считаются одной группой.
При отсутствии данных о происхождении независимость приближённо определяется
по уникальным каналам; полная проверка владельцев/перепечаток не выполняется.

Метрики отдельно показывают multi_source_qwen и source_promotions — прямые
направления по числу источников и пересмотры при пересечении порога.
Это отдельный маршрут от Gemma → Qwen по I₁ >= 50. При пересмотре сохраняется
накопленная стоимость предыдущего анализа. Версия маршрутизации обновлена:
старые результаты не подменяют расчёт по новым правилам.


## Qwen без reasoning

Первичная оценка выполняется google/gemma-4-26b-a4b-it, полный анализ —
**qwen/qwen3.6-35b-a3b**. Qwen получает полный профиль и контекст, но не оценку
Gemma. Проверка тем, пороги, лимиты источников и категорий сохранены.

Для всех новых запросов заданы reasoning_effort="none" и max_tokens=2048.
Полная карточка ограничена 150 словами и пятью фактами. На реальной проверочной
новости Qwen ответил за 6,1 секунды, вернул 1797 входных, 269 выходных и
0 reasoning-токенов; стоимость usage.cost — 0,04590284 единицы API.
Это единичный замер, не гарантия задержки или качества. Качество режима
без reasoning отдельно не откалибровано.

Чтобы применить изменения к уже работающему процессу, остановите его Ctrl+C
и повторите прежнюю команду с тем же output-dir. Завершённые результаты,
включая ранее выполненный полный анализ Gemma, сохранятся. Новые запросы
полного анализа выполняются Qwen без reasoning. Для полного пересчёта
используйте новый output-dir.

analysis_kind различает screening и full. Фактическая модель каждого запроса
сохраняется в model, количество reasoning-токенов — в телеметрии.
